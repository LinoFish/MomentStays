# PhotoScan

A UI- and engine-independent Swift package for scanning image assets visible to Photos. Add the package to the app and provide `PhotosLibrarySource()` plus an async `MotionPhotoRecognizer` closure to `PhotoScanner`. The closure receives a `PhotoOriginalResource` with the complete, original, unmodified still bytes, original filename and Photos uniform type identifier and must return true **only** for a positively validated Android Motion Photo; false means confidently static/unsupported, and throwing means inspection failed. Connect the conversion engine's actual detection API in the app shell; this package deliberately has no engine dependency. For the URL-based `ConversionEngine.inspect`, the shell must write these exact bytes to a private temporary file using `resource.temporaryFileURL()` to preserve the original extension (or derive one from its UTI), bridge its completion asynchronously, remove the file on all paths, map `.motion` to true, `.staticImage` to false and `.unknown` or failures to a thrown error, and forward task cancellation to a fresh `InspectionCancellation`. The scanner does not guess from filenames, Photos Live Photo flags, or thumbnails.

Call `try await scanner.scan(progress:)` from a task. It requests Photos **read-write** access, returns authorization including limited/denied/restricted, and reports matches as Photos local identifiers. Limited access scans only the selected assets; access or resources can change during a scan. The async progress callback is awaited in order and runs off the main actor and counts processed assets, including unavailable or failed items, starting at zero; it carries snapshots of authorization, matches, matched resource identities and issues so the app can retain partial results after cancellation. Do not describe unavailable items as checked negatives. Cancel the caller task to stop; cancellation throws rather than returning partial results. Recognition must cooperate with cancellation for prompt interruption.

Only `.photo` original resources are read through `PHAssetResourceManager`, without network access or rendering. An original that cannot be read, including an iCloud-only original, is reported as `originalUnavailable`; Photos does not reliably distinguish a cloud-only resource from every other read failure here. No automatic download is attempted. Failed recognitions are `recognitionFailed`, not matches. Multiple original photo resources must all be readable; otherwise the asset is unavailable. Select the resource identified in `matchedResources`, not simply the first original, and revalidate it after rereading: library contents and authorization can change. Data is buffered in memory, so large originals consume memory. Live Photo paired videos, edited versions, videos, and inaccessible library items are not scanned. The app must provide `NSPhotoLibraryUsageDescription` in its Info.plist before requesting permission. Test actual permissions, iCloud behavior, and representative vendor files on a device; unit doubles cannot simulate Photos itself.
