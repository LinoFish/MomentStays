## 1.0.5 轨道选择和独立辅助轨

新增辅助轨检查通过：真实 2048 像素单帧辅助轨独立无音频导出，保留压缩包哈希与 PTS；主轨 Live Photo 加独立辅助 MOV；单帧不能冒充动态视频；使用由原始视频构造的双轨容器验证可选择第二轨（track ID 99）制作 Live Photo，保留原始封面与 PTS；辅助轨封面超出范围时拒绝且不切回主轨；原片没有辅助轨时明确报告。

独立导出允许单帧，不添加封面标记、音频、重复帧或插值。导出清单支持单辅助 MOV、JPG+MOV 配对及配对加辅助 MOV 三种布局；续转校验覆盖每个输出。

测试集中的辅助轨为 2048×1536 单帧。默认导出时，零时长样本按预期报告失败；开启默认关闭的高级修复后，测试样片成功导出。修复只修改导出副本时长，不修改原片、压缩样本或样本起始时间；专项测试验证未开启修复时不会自动改时长。

原有 32 项原生转换、30 项 Python 单元测试以及文件名保留和批量输入回归均通过。最终「照片」图库导入及 iPhone 实机显示仍未测试。

## 1.0.6 小米 AAC 缓冲区分组误报

新增动态照片测试样片可在旧版复现 `Movie presentation timeline shifted`。源音频与输出 MOV 的压缩包相同，AVAssetReader 将它们组合成不同的缓冲区。旧校验比较缓冲区起始时间并误报位移；实际逐包 PTS 未改变。

TrackInfo 改为使用 CMSampleBufferGetSampleTimingInfo 逐样本获取时间，并记录每个样本大小。输出验证核对实际样本数量、大小序列、整体压缩数据哈希和逐样本 PTS，保留原有位移阈值。没有重编码、移动时间或放宽校验。

`scripts/check_xiaomi.py`：3 张均成功；每张 89 个音频包，音视频 PTS 位移为 0。另从输入 MP4 / 输出 MOV 的原始 stsz、stts 表独立核对音频包大小与时长序列，静态图压缩数据、原始封面时间和输出文件哈希均通过。原有 32 项原生转换、辅助轨专项、批量导入、文件名保留和 30 项 Python 单元测试通过。

Core Media 接口语义依据：[Apple CMSampleBufferGetSampleTimingInfo](https://developer.apple.com/documentation/coremedia/cmsamplebuffergetsampletiminginfo(_:at:timinginfoout:))。

最终 137 张全量回归：134 成功、0 失败、3 张原有静态照片跳过。134 组输出主 JPEG 压缩数据、辅助图、原文件名及输出文件哈希独立核对通过；音视频样本 PTS 位移均为 0，封面采样对齐最大偏差约 10.778 微秒；137 张原片哈希保持。从 1.0.6 最终 ZIP 解压后的应用实际启动并正常退出，签名检查通过，包含 x86_64 与 arm64，内置帮助版本为 1.0.6。
