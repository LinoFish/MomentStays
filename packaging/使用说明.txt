Motion-Live 1.2.0 — Android 动态照片 ↔ Apple Live Photo
适用于 macOS 12 或更新版本，兼容 Intel 和 Apple Silicon。

1.0.6 修复：部分小米动态照片转为 MOV 后，系统会重新分组 AAC 音频包。旧版按读取缓冲区比较时间，误报 Movie presentation timeline shifted。新版逐个实际样本核对时间、大小和压缩数据，音视频均不重新编码，原封面时间及文件名保持。

安装
1. 将 Motion-Live.app 拖到「应用程序」，或解压后直接打开。
2. 无需安装 Python、Swift、Xcode、FFmpeg、ExifTool 或 Homebrew。
3. 此版本使用本地签名，尚未经过 Apple 公证。通过网络收到后，首次打开可能被系统拦截。
   macOS 12：在访达中按住 Control 点按应用 →「打开」→ 再点「打开」。
   也可以在「系统偏好设置 → 安全性与隐私 → 通用」中允许本次打开。
   新版 macOS：尝试打开后，在「系统设置 → 隐私与安全性」中查看「仍要打开」。
   请仅打开你信任的来源发来的应用。

使用
1. 将多张 Android 原始动态照片或多个文件夹一起拖进左侧；点击「选择原片」也可按 Command / Shift 多选。文件夹自动扫描子文件夹，重叠选择只处理一次。
2. 选择原片目录之外的保存位置。默认保存到原片文件夹旁的新文件夹。
3. 点击「开始转换」。原始文件不会被修改或删除。
4. 每张照片生成一个普通 .livephoto 文件夹，里面包含保留原文件名的 JPG/JPEG/HEIC、同名 MOV 和校验清单。
5. 在 Mac「照片 → 文件 → 导入」中选择输出目录，将图片和 MOV 一起导入。
   在「照片」中确认能播放后，可用 iCloud 照片同步至 iPhone，或从「照片」进行分享。

画质与 HDR
• 静态 JPEG 主图不重新编码，音视频压缩数据直接复制并校验。
• 已有 Ultra HDR 的主图、增益图与 HDR 解释数据保持原样；不额外转 HDR 格式。
• 普通 SDR 保持 SDR，不生成或推测增益图。
• 默认尝试把可识别的旧 Apple Gain Map（版本 65536、亮度参数完整）转换为 Ultra HDR。
  此时只转换增益图，主图不重新编码。不能安全解释的旧版 HDR 保留原格式，并说明原因。
• 本机不需要能显示 HDR；最终效果取决于观看设备、系统、相册和同步方式。

封面时间
使用原始 Google 新/旧封面时间，检查视频样本时间和 edit list 映射。
写入 Apple 封面定时轨后会重新读回验证；不会用视频截图替换原始高分辨率封面。
缺少时间或不同时间轴对应不同帧时，默认报告错误，不悄悄改成中点。
「高级设置」中可主动允许中点，或指定 media / presentation 时间含义。
选中列表中的照片可查看原因；「查看报告」会在应用窗口中显示全部结果。
需要时可在报告窗口中点「在访达中显示原始报告」定位 JSON 文件。

续转与停止
相同原片、设置和已校验输出会自动跳过。已有不同结果不会被覆盖。
停止会等待当前文件清理后结束，已成功输出的文件保留，可以稍后继续。
转换只在本机处理。「照片图库」入口仅在用户授权和选择后读取实况资源，可能由系统下载 iCloud 原件；不修改图库。

范围与已知限制
支持 Google/小米兼容 JPEG、华为/荣耀 LIVE_、三星 SEF、OPPO/vivo 单文件 JPEG。
新增三星 mpvd/SEF HEIC（限已验证布局）；其他 HEIC/AVIF 暂不完整支持。暂不支持 vivo 旧双文件、任意拆开的图片/视频；不承诺所有型号和私有 HDR。
不从普通旧 Pixel HDR+ SDR 成片凭空恢复 HDR。
复杂编辑时间轴、负数媒体 PTS 等不能安全处理的文件会报告错误。
Intel/macOS 12 已本机测试；Apple Silicon 版本已交叉编译，尚未在真实 ARM Mac 上运行验证。
已验证本地与公开的 Ultra HDR 测试样片；最终 iPhone 相册的 HDR/封面效果仍需实机验证。

参考：Google Motion Photo / Ultra HDR 规范，Apple HDR Gain Map 说明，
LivePhotoTools、live_motion_photos_convert；实现为独立原生代码，不捆绑第三方运行库。

1.0.1：修复携带 Extended XMP 的 Google / Pixel 动态照片无法识别的问题。支持多分片重组、校验和无关扩展元数据原字节保留。

1.0.2：支持多选、同时拖入多个文件 / 文件夹和访达多文件打开。只转换所选文件及文件夹中的照片，同名文件按原相对路径分开输出。

1.0.3：支持带主视频与辅助影像双轨的 Google 动态照片。按格式规定选取主运动轨，原始 JPEG 继续作为封面；辅助影像轨不加入 Live Photo 视频。主视频和音频不重新编码并逐包校验。
主 XMP 缺失但视频完整时，可从 Google 视频元数据恢复原始封面时间，报告会注明恢复来源。缺少视频的编辑版静态照片会跳过；不会编造运动内容或封面位置。

1.0.4：保留原照片的完整文件名，MOV 使用相同名称主体。已有 1.0.3 输出经过哈希检查后可以只恢复文件名，无需重新编码；设置和原片必须一致。已经导入 Apple「照片」的项目不会自动改名，需要重新导入恢复文件名后的文件。
辅助视频轨用于保存额外替代画面，转换后的 MOV 只保留主运动轨及音频。辅助画面仍保留在原始 Google 文件中，Live Photo 不能替代完整原片归档。

1.0.5：视频轨选择与辅助轨导出
•「视频轨」可选择主运动轨或辅助影像轨。选择辅助轨制作 Live Photo 时，必须至少有两帧，且能对应原始封面时间；不符合时报告原因，不切换为主轨，不延长、循环或生成画面。
•「导出」可选择「仅 Live Photo」「Live Photo ＋ 单独导出辅助轨」「仅单独导出辅助轨」。
• 独立辅助轨保存为「原名称主体.auxiliary.mov」，保留原分辨率、原始样本时间和压缩数据，不含音频、配对标识或封面标记。一帧辅助轨也可导出，但不会因此变成连续动态视频。
• 仅辅助轨模式使用普通 .auxiliary-export 文件夹，含 MOV 与校验清单；不输出 JPEG，也不转换 HDR。
• 同时导出时，.livephoto 文件夹里有 JPEG、配对 MOV、独立 auxiliary.mov 和清单。导入「照片」时只选择同名 JPEG 与配对 MOV；辅助 MOV 请单独保存。
• 没有辅助轨的文件在请求辅助轨时会报告原因。已有输出与所选模式不同时不覆盖，请换新的输出位置。

• 高级设置「独立导出时允许修复辅助轨的零时长」默认关闭。有些原片有一帧编码画面，但 stts/mdhd/tkhd 时长为 0，系统因此读不到画面。勾选后只针对这种布局，使用主轨最短有效帧长修复辅助样本的显示时长。
  这会改变导出辅助视频的时长，不改变压缩画面、样本起始时间或原始文件；清单记录原时长 0、采用的帧长和原压缩样本哈希。不会把该单帧轨转换成连续 Live Photo 视频。

1.1.0 厂商、HDR 和静态照片清理
• 华为/荣耀 LIVE_ 尾标按原封面帧号读取实际视频 PTS，不按平均帧率估计。
• 三星按 SEFH/SEFT 目录定位 MP4；OPPO 用 VideoLength 排除额外尾挂；vivo V2 使用标准容器与私有命名空间。
• 输出 JPEG 只保留完整静态 JPEG 图像及增益图，不保留内嵌视频、音频、非图片填充和动态照片尾标。视频和声音只在独立配对 MOV 中。
• 对有完整参数的 ISO 21496-1 JPEG 增益图尝试补充 Ultra HDR 元数据，主图和增益图均不重编码。已有 Ultra HDR 不转换。旧 Apple 增益图转换继续保留。
• 旧厂商 HDR 若无可验证的增益/亮度参数，保留已有静态数据并报告，不凭空生成 HDR。
• 原始封面时间超出视频内容时仍明确报错，不以视频中点或最后一帧替换。

1.1.1 已有输出处理
• 遇到已有结果会询问「跳过」「覆盖」或「停止本次任务」，可勾选将选择应用于本次所有已有输出。
• 跳过不校验或改写已有文件，也不会计为转换失败。
• 覆盖会替换该照片的整个输出文件夹。先在临时位置完成转换与校验，成功后原子替换；失败或停止时保留旧结果。
• 已有清单损坏、内容或设置不同，也可以通过明确选择覆盖重新生成。

1.1.2 可选数据文件与厂商显示
• manifest.json 是校验清单，report-*.json 是批量日志；均不是导入 Live Photo 的必需文件。
• 主界面取消「导出校验清单和 JSON 报告」后，本次只导出 JPEG/MOV 等媒体文件，仍会完成全部转换校验；本次报告仅在应用内保留，退出或开始新任务后不再保留。
• 关闭后无法依靠清单自动验证旧结果，已有输出仍会询问覆盖或跳过；不会删除输出目录里更早的 JSON 报告。
• 列表新增「厂商」，优先依据原片 EXIF Make 识别；缺失时只对明确的厂商格式显示格式归属，通用 Google 格式不会直接认作 Google 机型。悬停查看识别依据及型号。

1.1.3 荣耀私有 HDR 与窗口高度
• 能区分本次荣耀 EHDR 私有样片和标准 Ultra HDR。私有扩展逐字节保留并校验，暂不能可靠转换为 Ultra HDR；Apple 显示 SDR，结果详情明确提示。保留不等于验证了荣耀相册重新导入兼容性。
• 旧版曾清理掉私有扩展的输出需要选择覆盖重新生成。未知扩展版本或无效长度会报错，不静默丢弃。
• 原图主 JPEG 不重新编码，已有 Ultra HDR 增益 JPEG 不变；SDR 不生成增益图。输出 JPEG 不再附带动态 MP4 或音频。
• 窗口最小高度降为 540，缩小时可纵向滚动访问底部按钮，放大时列表扩展。

1.1.4 三星 HEIC 动态照片
• 新增三星 mpvd + SEF/mpv2 HEIC 单文件格式。支持多选、文件夹扫描、拖放及原文件名导出。
• 保留 HEIC 原始图像编码（含分块、缩略图、色彩及方向属性），只更新配对 EXIF 和动态 XMP；不转 JPEG，不重新编码静态图。
• 从导出 HEIC 删除整个 mpvd 视频/音频和 SEF 动态尾部，动态画面和音频放在独立 MOV。
• 使用原始 XMP 封面时间，并映射到实际视频帧；无有效封面仍默认报错。不同 HEIC 存储结构可能不支持，不能代表所有厂商 HEIC 兼容。
• HEIC 的编码和色彩属性保留，未新增或转换 HDR；HDR 渲染未做手机真机验证。

1.2.0 紧凑界面
• 压缩顶部说明、路径卡片与统计区域，列表行高调整为 28，给照片队列更多空间。
• 输出设置集中在两行面板，较长说明通过悬停提示查看，原有选项及默认值保留。
• 底部采用单行操作栏：状态和任务进度在左，打开输出、报告、停止、主操作在右；仅任务进行时显示进度条。
• 修正转换时状态列刷新位置，支持浅色/深色模式和 900×540 小窗口。


1.2.0 新增：苹果实况转安卓
• 顶部切换「苹果实况 → 安卓」，选择完整的 JPEG/HEIC 与 MOV 配对，或点「照片图库」。
• 通过 Apple 内容标识匹配视频，封面来自 still-image-time 定时轨；不按文件名或中点猜测。
• 目标支持 Google/通用、小米、三星、华为、荣耀、OPPO、vivo V2。不同手机固件的识别和 HDR 显示需要真机验证。
• JPEG 默认 Ultra HDR；SDR 不额外生成增益图。只有受支持、参数完整的旧 Apple HDR 才转换增益图。
• 主图和新增增益图的 JPEG 质量分别可调。默认保留 JPEG 原图编码；关闭该选项才重新编码 JPEG 主图。已有 Ultra HDR 的增益图原样保留。
• Google/小米/三星可选择 HEIC 保留原编码，输入须为 HEIC；不承诺安卓能显示保留的 Apple 私有 HDR。
• 输出为独立 .motionphoto 文件夹，里面是含视频的 .MP.jpg 或 .MP.heic，以及可选 JSON。静态独立导出仍不保留视频或音频。
• 已有结果可选择覆盖或跳过；关闭 JSON 后无法依靠清单验证续转。
• 可把窗口收窄到 390 像素。设置收起以节省空间，展开后可滚动；底部操作始终保留。当前安装包仍仅适用于 macOS，尚非 iOS app。
