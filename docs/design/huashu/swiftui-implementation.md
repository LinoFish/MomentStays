# 原生工作台实现

依据用户确认的第一个方案，沿用原生 SwiftUI 与 macOS 12 部署目标。

- 宽窗口采用左侧队列范围、中间照片内容、右侧交付设置；底部固定任务状态与转换操作。
- 队列按全部、已完成、需处理筛选；「最近结果与交付」继续打开真实历史任务。
- 照片支持缩略图和列表两种显示；窄区域自动用列表；选择状态保存在 WorkspaceModel 中。
- 缩略图通过 ImageIO 在后台生成，最长边 480 像素，内存缓存最多 96 张、成本上限 32 MiB；读取失败时显示系统图标占位。
- 图库来源继续使用现有平台服务准备的本地资源；本次没有新增 PhotoKit 访问路径。
- 筛选只影响显示。选择非全部范围时主要操作明确写「转换全部来源」，不改变现有引擎对来源的批量处理语义。
- 保留源文件菜单、拖放导入、文件详情、扫描、停止、报告、交付重试与共享。
- 深浅色模式均使用系统背景与系统强调色，跟随用户的 macOS 外观和强调色偏好。窄窗口收起侧栏与检查器，队列标题提供范围选择，导出设置通过原有面板打开。

形式来自内容：照片网格用于辨认来源，常驻检查器用于确认去向，底部任务区让批量转换的进度与操作持续可见。

应用顶部使用与 GitHub main / 官网相同的官方品牌图标，加载应用包的深浅色 ICNS。预览占位也使用同一个官方 Logo；缩略图角标仅显示媒体类型文字，避免与品牌标志混淆。


用户进一步要求：「应用顶栏和预览图的icon要用和logo一致的图标，ui色调应该和系统一致，或者用品牌的琥珀色」。本轮选择系统配色，Logo 自身保留官方琥珀色，不另设青灰色主题。
