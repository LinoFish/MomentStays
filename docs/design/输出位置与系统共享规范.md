# 输出位置与系统共享规范

状态：1.3.0 已接入原生系统共享、持久任务缓存和最近结果重试。自动测试不调用外部共享服务或发送文件；LocalSend 与接收设备仍待实际验收。

关联：[当前交互预览](swiftui-ios-preview.mockup.html)、[系统图库识别与自动入册规范](图库识别与自动入册规范.md)。

## 1. 命名与位置

界面“保存位置”统一改为“输出位置”，“来源与保存”改为“来源与输出”。输出位置表达文件夹、图库相册或系统共享目标，不应始终显示为磁盘路径。

当前设计稿在 Apple 实况 → 安卓方向的输出位置卡片中展示输出方式。宽屏与窄屏使用相同名称和状态；窄屏不把共享入口藏到高级设置中。

## 2. 输出方式

| 方式 | 文件去向 | 完成后的操作 |
| --- | --- | --- |
| 保存到文件夹（默认） | 用户指定的独立文件夹 | 查看结果，可手动共享 |
| 转换后直接共享 | 应用管理的任务缓存，无须用户先选文件夹 | 全批次结束后，对成功文件打开一次系统共享菜单 |
| 保存到文件夹并共享 | 用户指定的独立文件夹 | 全批次结束后，对成功文件打开一次系统共享菜单 |

“直接共享”只在 Apple 实况 → 安卓方向开放。本次不改变 Android → Apple 的文件输出与自动入相册方案。

直接共享模式下隐藏“更改位置”，路径改为“任务缓存 · 转换后共享完整文件”。其他两种模式显示文件夹路径与位置选择入口。任务执行时锁定输出方式，避免处理中改变文件去向。

自动弹出菜单是用户选择该输出方式并启动转换后的任务行为，不代表预先指定 LocalSend，也不自动选择接收设备。

## 3. 共享流程

1. 完成转换与媒体校验，汇总成功输出文件。
2. 使用实际文件 URL 构建系统共享菜单；批量任务在结束后统一弹出一次，禁止每张照片弹一个菜单。
3. 用户选择 LocalSend 或其他系统提供的共享服务，并在该服务中选择安卓设备、完成发送。
4. 结果区保留“共享文件”入口，可再次共享，无须重新转换。

部分成功时只共享成功文件，并显示失败数量；全部失败或任务被用户停止时不自动弹出菜单。已完成文件仍可通过结果入口手动共享。

用户取消菜单、取消发送或共享服务报错，不改变媒体文件“转换成功”的状态，不删除结果。

## 4. 文件与画质要求

共享载荷必须是最终 `.MP.jpg` / `.MP.heic` 完整文件。JPEG 主图、增益图、HDR 元数据、嵌入视频和视频中的音频作为同一文件交付。

- macOS 使用文件 URL，不传 `NSImage`、缩略图、截图或只有静态主图的数据，避免框架按普通图片重新编码。
- 默认不共享 JSON 清单、报告、`.motionphoto` 目录或独立配对 MOV。
- 文件名保持最终输出名称，多张同名文件在共享暂存区安全消歧，不能覆盖别的结果。
- 不为共享额外压缩、改变照片分辨率、移除增益图或重新编码音视频。
- HEIC 的原编码保留规则、JPEG 主图/增益图质量设置均沿用转换步骤；共享阶段不再次加工。
- 第三方服务仍可能改变文件，不能仅凭本应用使用文件 URL 就保证接收端字节不变。验收需对实际接收文件进行 SHA256、HDR、动态视频与封面检查。

## 5. 系统接口与 LocalSend

macOS 12 原生实现采用 `NSSharingServicePicker(items:)`，传入最终文件 URL，在主线程从稳定的按钮或结果区域展示。未来 iOS 使用原生系统分享面板，文件载荷和任务规则保持一致。

菜单由系统根据文件类型和已安装、启用的共享扩展生成。不硬编码“LocalSend 必定可用”，不将 LocalSend 作为应用必需依赖。其共享扩展可能因版本、分发渠道或启用状态而不同，必须在 macOS 12 实测。

LocalSend 未显示或无法接收文件时，保留“查看文件”和再次共享入口；直接共享模式同样提供定位任务缓存文件的方式，便于用户在 LocalSend 中手动选取。不得通过转为 `NSImage` 等方式牺牲动态/HDR 数据以强行让某服务出现在菜单中。

本需求不实现 LocalSend 协议、设备发现或网络发送，也不强制安装或启动特定应用。

## 6. 状态与缓存生命周期

转换状态和共享状态独立记录：待转换、转换中、已转换；待共享、已打开菜单、已交给共享应用、已取消、共享调用失败。

系统服务的完成回调不一定代表远端安卓设备已收到原文件。没有可靠的端到端确认时，不显示“已发送到安卓”或“已接收”。只有第三方流程明确返回相应证据时，才可使用更具体的状态。

任务缓存由应用管理，不能放入一退出即无条件删除的目录。文件至少在共享菜单及服务读取期间保持可用；取消、失败后仍可重试共享，应用重新打开后可找到未清理任务。

提供明确的缓存清理入口，显示待共享/共享中的任务并避免删除其资源。具体自动过期策略单独实现和验证，不把“系统已接手”作为立即删除文件的依据。用户指定文件夹中的输出不随任务缓存清理删除。

共享恢复只重复交付已校验文件；转换设置或来源改变时才需要重新转换。

## 7. 与图库方案的关系

Android → Apple 可将结果创建为 Live Photo 并加入指定 Apple 相册，规则遵循图库规范。

Apple → Android 默认文件夹输出，也可直接共享到安卓设备。两者均不承诺把安卓单文件导回 Apple「照片」后成为可播放的实况照片。

图库读取权限只在来源需要时申请；系统共享目标的设备选择、网络权限及接收确认由目标共享应用处理。共享动作由用户发起，本设计稿不执行真实发送。

## 8. 设计稿行为与验收

设计稿切换到“苹果实况 → 安卓”后，输出位置卡片出现三种输出方式。选择直接共享会切换位置提示；示例任务完成后展示共享流程提示，并显示“共享文件”按钮。所有提示标明设计示意，不冒充真实系统菜单，也不真的调用 LocalSend。

原生实现验收至少包括：macOS 12、LocalSend 可用/不可用、单张/多张、部分失败、取消、停止、共享失败重试、应用重启、缓存清理、文件夹并共享、同名输出，以及共享前后 JPG/HEIC 文件字节与动态/HDR 结构核对。确认主线程不会被转换阻塞，窄屏底部操作不溢出。

## 10. 1.3.0 原生接入

输出位置菜单和设置区均可选择输出方式；批次结束仅对成功结果发起一次系统菜单，停止时不自动共享。传递最终文件 URL，共享暂存副本经 SHA256 检查，重复名称保留 `.MP.jpg` / `.MP.heic` 后缀。任务记录与副本保存在应用支持目录，退出后保留，可从“最近结果”再次交付、查看或清理。

共享期间禁止替换来源、转换参数和清理资源。服务回调只表示交付给共享应用，不能据此宣称远端收件成功。未实现 LocalSend 协议或网络发送。
