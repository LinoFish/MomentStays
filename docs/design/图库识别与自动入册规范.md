# 系统图库识别与自动入册设计规范

状态：1.0 已接入 macOS 原生图库流程、持久去重和运行期间监测。文件转换与隔离状态测试已覆盖；真实图库写入、iCloud 和 HDR 显示仍待人工验收。

适用范围：macOS 12 及以上；后续 iOS 复用转换任务与去重逻辑，图库权限、选择器和后台运行方式按平台适配。本次实现不访问真实用户图库进行测试；只有用户主动进入图库功能或启动入册任务后才申请授权。

补充规范：[输出位置与系统共享规范](输出位置与系统共享规范.md)，统一“输出位置”命名，并定义 Apple → Android 的直接共享与文件夹并共享流程。

关联：[双向转换与格式范围](../product/双向转换与移动布局.md)。本规范描述图库流程，界面实现见 SwiftUI 工作区。

## 1. 目标与边界

形成“读取系统图库 → 自动识别动态照片 → 转换 → 校验 → 导入指定相册”的完整流程，减少手工导出原片和拖入照片应用的步骤。

- 通过公开 PhotoKit 接口访问系统照片图库，不直接读写 `.photolibrary` 内部数据库或资源目录。打开其他图库不等于切换系统图库。
- 首次进入图库功能时申请所需读取/写入权限，不在应用启动时自动请求。应用启动与自动测试不触发授权。
- Android → Apple：将转换后的静态图片和配对 MOV 创建为一张 Live Photo，并加入目标相册。
- Apple → Android：默认导出安卓动态文件到文件夹，也可直接共享或保存到文件夹并共享，具体遵循输出共享规范。不得把“保存进 Apple 照片”表述为“在 Apple 照片中可播放的安卓动态照片”；其识别、视频保留及 HDR 显示需要额外验证。
- 不删除、覆盖或调整来源资产。写入产生独立的新资产；相册是资产的组织方式，不是另外复制一份媒体文件。

## 2. 自动识别规则

| 来源类型 | 识别方式 | 处理结果 |
| --- | --- | --- |
| Apple Live Photo | PhotoKit 的 `photoLive` 标记，进一步检查完整配对资源 | 可进入 Apple → Android 队列 |
| Android Motion Photo JPEG / HEIC | 枚举图库图片资源，按需读取原始文件，通过现有厂商、XMP、容器和视频边界解析识别 | 可进入 Android → Apple 队列 |
| 普通静态照片 | 检查后无动态资源 | 跳过，不列为转换失败 |
| 带动态标记但无完整视频 | 视频已丢失、资源不完整或容器损坏 | 显示具体原因，不猜测恢复 |
| 本应用生成的资产 | 本地来源/目标标识记录 | 排除自动处理，防止转换循环 |

不能仅凭 `.jpg`、`.heic`、文件名或 HDR 标记判定动态照片。Android 动态图被导入、编辑或分享后，图库中的原始资源是否仍保留视频，必须读取验证；已丢失的视频无法凭静态图片恢复。

第一次扫描先读取资产元数据，分批检查候选资源。界面区分“扫描资产”“读取原件”“识别格式”的进度。先显示可用结果，不等全库原件下载完才呈现列表。

## 3. 原片、编辑版、HDR 与封面

- 默认读取未修改原片，优先保留原始画质和 HDR 数据。
- 使用原始版本时，配对为 `photo` 与 `pairedVideo`；封面时间对应原始 MOV。
- 用户选择保留当前编辑效果时，只使用相互对应的 `fullSizePhoto` 与 `fullSizePairedVideo`；两者缺失其一时说明原因，不静默混用原片与编辑版。
- 编辑后丢失增益图的照片标注“编辑版无 HDR 增益图”。不挪用原片增益图，也不为 SDR 自动生成增益图。
- 始终读取完整原件和配对视频，不用缩略图、预览 JPEG 或视频截图代替原始照片。
- 封面依据对应视频的定时元数据和时间线验证。来源版本改变后，封面可以不同；不能固定套用原片封面或视频中点。
- HDR 的转换、保留和未知格式处理沿用现有引擎规则。macOS 12 本机能否显示 HDR，不作为文件是否正确转换的唯一判断依据。

## 4. iCloud、任务与失败处理

完整资源可能只在 iCloud 中。首次扫描可以识别为“需下载原件”，在用户启动任务或允许下载后按需获取，不因扫描图库而无提示下载全部原片。

任务阶段：待检查 → 待下载／读取原件 → 转换 → 校验 → 导入图库 → 加入相册 → 完成。任何阶段可以显示具体失败原因。

- 下载和读取可取消，保留已完成结果。系统正在提交的图库变更不能假定可撤销，停止时先核实其最终状态。
- 转换失败时不创建图库资产。
- 转换成功、导入失败时保留已校验文件，只重试导入。
- 资产已创建、加入相册失败时，只重试相册关联，不能再次创建同一资产。
- 目标相册被删除、权限撤销、系统图库不可用、磁盘空间不足、iCloud 下载失败应分别报告，不统一显示“转换失败”。

## 5. 直接导入 Live Photo

使用 `PHPhotoLibrary.performChanges`，在同一个 `PHAssetCreationRequest` 中添加 `.photo` 和 `.pairedVideo`，创建一个资产。独立导出辅助轨不作为配对视频附加。

导入前必须通过现有媒体校验：图片/视频内容标识匹配、视频含有效封面定时标记、图片无残留嵌入音视频、媒体文件完整、时间线与源数据一致。

- 通过资源创建选项提供原始文件名；资产拍摄日期和位置优先采用来源图库信息，缺失时才使用可信的文件元数据。
- 不把 JSON 清单作为照片资源导入；关闭“导出清单与报告”不影响图库导入。
- 默认目标相册名为“留刻转换结果”。允许选择其他用户相册；仅在需要写入且获得授权后创建相册。
- 不默认复制原照片的全部相册归属，不对人物、回忆、系统智能相册分类作迁移承诺。
- 导入采用复制语义（`shouldMoveFile = false`）。任务文件在提交完成前必须存在；只有来源、输出保留策略和入库校验均确认后，才清理应用自己的临时副本。
- PhotoKit 写入完成后，以新资产标识重新读取，确认它是 Live Photo、存在图片与配对视频，并核对文件名、日期、位置及目标相册归属。失败状态不能提前显示为“已导入”。
- 导入后的图库资源与各系统对 HDR 的处理，需要在真实图库中验证，不仅依靠磁盘输出测试。

## 6. 去重、续转与防止循环

本地保存任务记录，不把 JSON 输出清单作为唯一去重依据。记录至少包含：来源资产标识、原片/编辑版选择、资源版本信息、转换设置、引擎版本、输出校验摘要、目标资产标识、目标相册标识和任务阶段。

- 来源内容、所选版本、设置和引擎版本均一致且目标仍存在时，跳过重复处理。
- 来源被编辑或引擎修复导致结果需要重建时，作为新任务处理；不自动删除旧资产。
- 自动监测排除全部已记录的本应用生成资产，不能只按相册名排除，以免移动相册后重新触发。
- 写入任务日志后再提交图库变更，及时记录创建请求获得的资产标识。异常退出后先核对目标是否已存在，再决定重试哪个阶段。
- 本地日志和 Photos 写入不是同一数据库事务。遇到崩溃导致状态无法确认时，标为“待核对”，不盲目重试创建，避免重复资产。
- 目标资产已被用户删除时，不默认自动补回，应标明缺失，交由用户再次启动处理。

## 7. 自动更新与 macOS 12 限制

第一阶段由用户手动启动扫描和转换；“转换成功后导入相册”为该任务的明确设置，不在首次运行时自动修改整个图库。

第二阶段可在用户启用后，利用 `PHPhotoLibraryChangeObserver` 监测应用运行期间的新增、修改和删除，只检查受影响资产。自动处理限于用户指定范围与方向。

macOS 12 不依赖 macOS 13 才提供的持久图库变更令牌 API。重新启动后重新枚举资产元数据，与本地记录核对，必要时再读取原件。

应用退出后不承诺继续监测或转换。登录启动、常驻进程与 iOS 后台任务均不包含在第一阶段，需后续单独设计。

## 8. 界面接入要求

沿用现有响应式设计稿的来源、输出位置、设置、照片队列和底部任务区：

- 来源区增加系统图库入口，进入后可限定扫描范围；明确当前使用系统图库。
- 图库扫描结果标明 Apple/安卓厂商、动态类型、原片/编辑版、HDR 状态和是否需下载原件。
- Android → Apple 的输出设置增加“转换后导入相册”，显示目标相册及是否同时保留文件夹输出。
- Apple → Android 继续以文件夹为默认输出目标，不承诺入 Apple 相册后具有动态播放能力。
- 进度区显示当前任务阶段；结果区分别统计转换成功、导入成功、重复跳过和失败。
- 扫描只读；用户启动启用了入册的任务后才写入。提示语应准确区分“来源不修改”与“会新增转换结果”，不能继续笼统声明“不会修改照片图库”。

原生入口已接入 SwiftUI 来源菜单、输出位置和设置区；HTML 设计稿仍为独立交互示意。

## 9. 实施顺序与验收

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| 一 | 手动扫描、筛选、转换、自动入册 | macOS 12 上从图库原件到可播放 Live Photo 的完整流程 |
| 二 | 去重、断点恢复、失败阶段重试 | 重复执行不重复创建；只重试失败阶段；自身输出不触发循环 |
| 三 | 应用运行期间增量监测 | 新增/编辑/删除识别；iCloud 下载；权限撤销；重启后核对 |
| 后续 iOS | 原生图库与任务适配 | 按 iOS 权限和生命周期重新验证，不宣称 macOS 窄屏即 iOS app |

第一阶段验收样本必须覆盖：Apple 原始实况、编辑版实况、完整安卓动态 JPEG/HEIC、已丢失视频的静态图、iCloud 未下载资源、同名照片、多次导入、导入后相册关联失败、取消与重新启动。实况播放、封面、日期、文件名、位置和 HDR 分别验证。

## 11. 1.0 实现与验证边界

实现入口为 `gui/PhotoLibraryService.swift`、`PhotosLibraryPicker.swift`、`DeliveryModels.swift` 与 `MacPlatformServices.swift`。图库扫描可限定相册，原片/编辑版不混配，iCloud 下载需勾选；普通静态图跳过。读取阶段显示进度，完成所选批次读取后加入转换队列，不逐张流式加入主队列。

Android → Apple 可选相册或文件夹并相册；Apple → Android 可选文件夹、系统共享或两者。任务和完整输出校验摘要保存在应用支持目录，最近结果支持再次交付、查看文件及手动清理自身缓存。照片原片不随缓存清理删除。目标资产缺失、提交状态不明、去重日志损坏时不会自动重新创建。

监测须在图库选择器中明确启用，只处理所选相册与方向，退出即停止。重新启用需重新扫描该范围；未实现后台常驻、登录启动或 iOS 应用。

隔离测试覆盖任务状态、去重决策、校验摘要、共享文件同名消歧、取消、记录恢复、缓存保护和真实引擎双向转换，不替代 PhotoKit 实际入库验收。真实图库、iCloud、第三方共享扩展与接收设备 HDR/封面仍需用户设备验证。
