# 照片队列分类与状态展示

状态：2026-10-27 已接入顶部分类、静态标记与任务快照。用户已同意将「待转换」「静态照片」「已完成」「需检查」放在队列顶部常驻显示，并保留「全部」入口。后续验收继续按以下要求核对。

## 目标与范围

用户无需逐张查看或打开筛选菜单，即可判断来源中哪些照片待转换、哪些仅为静态照片，以及哪些已有完成结果。沿用当前 SwiftUI 工作台、网格/列表和来源批处理语义，不改变转换引擎、输出及系统共享规则。

## 分类规则

| 分类 | 纳入条件 | 项目标签 |
| --- | --- | --- |
| 待转换 | 已识别的动态照片，尚无本次有效完成结果，且没有已知阻断问题 | 待转换 |
| 静态照片 | 扫描明确确认不含动态内容 | 静态照片 |
| 已完成 | 本次转换并校验成功，或已有结果通过续转校验 | 已完成；续转项可细分为已有结果 |
| 需检查 | 解析损坏、不支持的格式、动态资源不完整、缺少必要信息或转换失败 | 需检查／失败，并可查看具体原因 |

分类必须互斥。「全部」以外的四类数量之和等于当前已识别队列数量。扫描尚未产出的项目不计入已识别数量，并明确显示扫描中，不提前判断为静态照片。

- 不以 `isMotion == false` 或「已跳过」直接判断为静态照片。必须是明确的非动态识别结果；损坏、无法解析、视频缺失等归入需检查。
- 不以「是动态照片」直接承诺转换成功；待转换只表示目前未发现阻断问题，转换时仍须执行原有完整校验。
- 缺少封面等信息时，按当前设置判断是否存在阻断；默认报错策略下归需检查。用户明确启用的推测或修复设置只在其适用条件得到确认时影响分类，不自动启用兜底。
- 失败项只归需检查，不同时计入待转换。后续重试成功后移入已完成。
- 因用户选择跳过已有输出而未转换、且未校验结果的动态照片，不计入已完成；保留在待转换，项目上说明「本次已跳过」及原因，避免误称已校验成功。
- 已完成表示媒体结果完成，不等同于已导入图库、已共享或接收设备已收到。交付状态继续独立展示。

## 位置与响应式布局

在照片队列标题下、网格或列表内容上方，常驻显示按以下顺序排列的带数量筛选控件：

1. 全部
2. 待转换
3. 静态照片
4. 已完成
5. 需检查

宽屏单行展示，窄屏两行排列。名称、数量和当前选中状态直接可见，不依赖下拉菜单、横向滚动或悬停。控件位于照片滚动区之外，不随列表滚动消失。不得挤出底部主要任务操作。

原左侧范围入口如继续保留，须与顶部筛选共享同一状态、名称和数量，不形成另一套筛选规则；顶部不因宽屏已有侧栏而隐藏。零数量分类仍保留，可切换并显示对应空状态。

## 照片行与卡片

- 网格、宽屏列表和窄屏列表均显示明确文字标签；静态照片显示「静态照片」，不只显示「已跳过」。
- 静态照片使用普通照片图标，完成使用对勾，需检查使用警告图标；颜色只作辅助，深浅外观和 VoiceOver 均能辨认分类。
- 状态标签区分当前分类与任务细节。例如分类为静态照片时，可补充「不含动态内容，不参与转换」；归入待转换但被用户跳过时显示跳过原因。
- 异常详情可通过现有详情区或操作入口访问，不靠悬停作为唯一说明方式。

## 计数、筛选与任务行为

- 数量始终基于当前完整来源队列，筛选只改变显示，不删除项目、不缩小任务范围。
- 已确认静态项在有效扫描后应直接记录静态跳过，不再进入转换、源哈希或已有输出覆盖询问。任务范围仍覆盖全部来源，实际媒体工作只派发需要处理的项目；静态数量单列，不占动态转换进度分母。来源变化与分类可信度规则见 [性能优化方案](../development/Swift引擎性能优化方案.md)。
- 默认显示全部。切换网格/列表、改变窗口宽度或展开设置，不重置当前筛选。
- 转换成功或失败时，数量与项目归属同步更新；已完成项目不继续计入待转换。
- 转换期间保持用户当前筛选，不自动跳转。当前处理项目的名称和进度仍在固定任务区可见，避免项目移出当前分类后任务看似消失。
- 等待和正在处理的项目在尚无终态时保持其原有分类，实际执行阶段单独显示。停止后保留已完成结果，未处理项目继续待转换，静态照片不计为失败。
- 筛选结果为空时显示具体文案，例如「暂无待转换照片」「当前来源中没有静态照片」「暂无已完成结果」「没有需要检查的照片」，不得误显示为未添加任何来源。
- 非全部范围下，主按钮明确写「转换全部来源」，说明分类只筛选显示；本需求不新增「仅转换当前分类」。
- 现有任务重新执行、重新扫描或设置改变时，分类沿用有效任务状态；不能只因为切换显示就把已完成结果重新判为待转换，也不能把过期结果继续称为已校验完成。具体失效处理须复用任务与设置版本规则，不在本需求中引入自动重扫磁盘。

## 当前整合情况

五类顶部筛选、宽窄窗口布局、设置相关的缺失封面分类、静态提前跳过和过期设置状态清除已接入。筛选仅影响展示；重新扫描会重新建立队列并清除当前任务结果，跨重扫保留已完成标记仍需后续完善。已完成输出再次运行时仍由引擎校验续转，不能仅凭界面标记跳过验证。

关键实现入口：[队列状态模型](../../gui/WorkspaceModel.swift)、[筛选范围](../../gui/InterfaceSupport.swift)、[照片队列](../../gui/PhotoQueueView.swift)、[工作台](../../gui/WorkspaceView.swift)。本规范不要求修改转换引擎的报告状态或持久任务格式。

## 验收标准

- 混合队列含 3 张待转换、2 张静态、2 张已完成和 1 张需检查时，显示全部 8，各分类计数准确且互斥，筛选显示一致。
- 损坏文件、动态标记存在但视频缺失、未知格式均不进入静态照片。
- 用户跳过未校验的已有输出，不增加已完成数；续转校验成功才计入已完成。
- 转换成功后待转换减一、已完成加一；转换失败后待转换减一、需检查加一。交付失败不把媒体完成状态改成媒体转换失败。
- 静态照片在卡片和列表上均直接可辨，普通照片图标与动态照片有区别。
- 390×540 窄窗口两行筛选可见；宽屏单行可见；队列滚动后筛选栏仍可操作，主要任务按钮不溢出。
- 筛选、网格/列表切换、窗口缩放、零数量空状态、停止与重新扫描分别验证；筛选不改变传给转换引擎的来源。
- 运行中结果自动移出当前分类时不跳转筛选，底部继续显示当前任务进度与停止入口。
- 键盘、选中状态、深浅外观、长名称及无障碍能正确读出分类和数量。

实施验证遵守项目约定：调试默认仅编译 Intel，不生成 ARM、通用版本、DMG 或 ZIP，除非用户另有明确要求。
