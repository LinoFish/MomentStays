# 仓库结构

仓库按平台划分。跨平台共享的转换逻辑只放在 `core/`，各平台目录只放该平台的界面、系统集成、构建脚本和测试。

```text
core/                  Rust 核心：解析、重封装、厂商写入、C ABI（所有平台共用）
  include/             C 头文件 momentstays_core.h（cbindgen 生成）
  src/compat/          从已停止维护的 Python 版移植的 Google 动态照片栈
apple/
  shared/              macOS 与 iOS 共用的 Swift 转换引擎，经 RustCore.h 调用 core
    tests/             引擎级测试驱动与基准（NativeDriver、RustBridgeDriver 等）
  macos/
    Sources/           macOS SwiftUI App
    packaging/         Info.plist、本地化、图标绘制、DMG 布局
    scripts/           macOS 构建、打包与回归检查脚本
      testkit/         检查脚本用的构造样片与格式检查工具（仅测试用）
    tests/             macOS App 层测试
  ios/                 iOS App、分享扩展、Engine / PhotoScan Swift 包
    scripts/           Xcode 构建阶段调用的 Rust 静态库构建脚本
windows/               （规划中）Windows App
android/               （规划中）Android App
scripts/               仓库级工具：发布审计、网站手册同步
docs/                  产品、设计、开发文档
```

## 约定

- 新平台放在仓库根目录下独立的目录（`windows/`、`android/`），通过 `core/` 的 C ABI（`core/include/momentstays_core.h`）调用核心，不要复制或改写转换逻辑。
- 只被 Apple 平台使用的代码放在 `apple/` 下；macOS 与 iOS 共用的放在 `apple/shared/`。
- 平台自己的构建与检查脚本放在该平台目录的 `scripts/` 下。脚本统一先切到仓库根目录，再使用相对仓库根目录的路径，例如 `bash apple/macos/scripts/build_app.sh`。
- `scripts/` 只放与平台无关的仓库级工具。
- Python 版转换器已不再维护。`apple/macos/scripts/testkit/` 里保留的 Python 代码只用于构造测试样片和检查输出，不作为实现参考；格式行为以 `core/` 和 `apple/shared/` 为准。
