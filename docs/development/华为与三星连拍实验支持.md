# 华为与三星连拍实验支持

接入方向为静态 JPEG 连拍 → Apple。只按已知文件协议及明确证据处理，不承诺新系统、新相机版本或全部机型兼容；尚未完成真实华为、三星整组样片与 Photos 成组验收。

## 华为

根据用户确认“华为与荣耀格式一致”，复用荣耀严格文件名协议：`IMG_YYYYMMDD_HHMMSS_BURSTnnn[_COVER].jpg/jpeg`。EXIF Make 必须为 `HUAWEI`，日期时间有效、序号为三位且大于零；COVER 作为来源代表帧证据。缺帧保留原序号，不补齐，也不声明已知原始总数。

使用独立 `huawei-burst` 来源和 `huawei-burst-1` 实现版本。分组按来源目录、品牌、EXIF Model 和文件名前缀隔离，与荣耀同名组不混合。未知尾部、新文件名、HEIC、实况组合不纳入本次兼容范围。

## 三星

首版限定：

- 原片 EXIF Make 为 `samsung`，文件名 `YYYYMMDD_HHMMSS_nnn.jpg/jpeg`，有效日期时间及三位正序号。
- 同时具有完整、有效的 SEFT 尾部目录，以及唯一 `0x09e0 / Burst_Shot_Info`。不能仅凭 `_001`、拍摄时间或相似图像成组。
- 本轮只接受目录版本 `106`、`107`、零记录标志、连续无间隙的记录范围。每条载荷必须为 1–32 字节 ASCII 数字；这是一项实验准入限制，不是对三星所有连拍载荷格式的断言。
- 除连拍条目外，仅允许同样编码受限的 `0x09e1 / BurstShot_Best_Photo_Info`、`0x0a01 / Image_UTC_Data`、`0x0c61 / Camera_Capture_Mode_Info`，名称和类型需对应且不重复。其他条目、二进制载荷、未索引资源、实况或未知版本均拒绝转换。
- 组内连拍载荷的 SHA-256 必须一致；它只作为额外一致性证据，不解释为已确认语义的全局组 ID。真正分组仍限定同目录、同机型及严格文件名组前缀。
- 不解释 `Best_Photo_Info` 的数值，不把第一帧猜成最佳帧。整组转换前用户需明确选择代表帧；独立照片输出无需猜测代表帧。

文件名参考 [Aves 的厂商连拍规则](https://github.com/deckerst/aves/blob/develop/lib/ref/bursts.dart)；SEF 条目名称及观察到的数字字符串参考 [ExifTool Samsung 源码](https://raw.githubusercontent.com/exiftool/exiftool/master/lib/Image/ExifTool/Samsung.pm)。资料不足以证明全部三星版本的载荷语义，因此不推广到其他命名或编码。

三星使用 `samsung-burst` 来源和 `samsung-burst-1` 实现版本。SEF 的范围、重叠和目录头校验与既有三星实况读取共用 [vendor.rs](../../core/src/vendor.rs)，不维护另一套容器解析。实况路线仍按原规则处理，不采用连拍的版本/载荷白名单。

Apple 标记写入后，重新解析三星 SEF，并核对 JPEG 图像编码、尾部完整字节、原片归档和输出清单。SEF 目录通过相对其自身位置的回溯偏移定位记录；头部增长后相对布局与尾部字节均保持。未确认的二进制载荷可能含绝对指针，因此本次不放行。

## 验证与剩余工作

本轮 92 项相关 Rust 回归及 13 项 Swift/Rust 数据传递检查通过。只读检查本地原始连拍候选，现有样片均为荣耀，未发现可用于华为/三星整组验收的素材；因此不把自动回归通过视为真实设备兼容性证明。

[跨品牌回归](../../core/tests/vendor_burst.rs) 使用构造 JPEG/SEF，覆盖华为分组及版本隔离、缺帧、归档与续转，三星手动代表帧、已知版本、原样尾部、部分扫描/选择、组证据冲突、独立导出、来源变化、损坏目录、未知版本/条目/编码及混合资源拒绝。既有荣耀、Google、三星/华为实况、扫描和导出测试也用于回归。

[Swift 工作区测试](../../apple/macos/tests/WorkspaceModelTests.swift) 的 `--google-burst-transport` 检查同时覆盖 Google、华为、三星的来源版本、序号、组计划和三星 SEF 一致性证据往返，避免 Swift 编解码遗漏新增字段。

仍需整组原片确认实际机型/系统版本、文件名和载荷取值，再决定是否扩展白名单。尤其是三星未知二进制 `Best_Photo_Info`、更多 SEF 条目、毫秒命名、不同序号宽度及 HEIC，均不得根据构造测试直接宣布兼容。实际 Photos 全成员成组及代表图结果仍以导入后回查为准。样片与报告按[本地样片与隐私](本地样片与隐私.md)仅保存在本地。
