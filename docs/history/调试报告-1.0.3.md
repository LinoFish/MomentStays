# 1.0.3 全量调试结果

Intel / macOS 12。输入：本地测试集中的 JPEG。测试不访问 Apple 照片图库。

| 版本 | 转换成功 | 转换失败 | 跳过 |
|---|---:|---:|---:|
| 1.0.2 复现 | 33 | 94 | 7 |
| 1.0.3 修复后 | 131 | 0 | 3 |

94 个原失败均因旧代码要求视频容器只能有一条视频轨。Google 格式允许主运动视频和辅助影像轨；现按容器顺序选主轨，保留原 JPEG 封面，不将辅助影像轨混入 Live Photo。依据：[Google Motion Photo 格式规范](https://developer.android.com/media/platform/motion-photo-format)。修复后 97 张双视频轨文件均成功（其中包含 3 张恢复识别的编辑副本）。

另恢复了 4 张主 XMP 缺失的副本：JPEG 后紧邻完整 MP4，其中 Google 封面描述符记录了原始时间。恢复的四个时间分别与对应未编辑原版的 XMP 交叉核对一致；没有使用视频中点。

所有成功文件保留原始静态 JPEG 压缩数据，辅助 JPEG 保持原字节，主视频及音频压缩包逐包校验，媒体 PTS 位移为 0。原始封面时间写入清单，并与实际视频帧对齐。源文件未修改。

成功结果位于项目 converted-1.0.3 中，每个 .livephoto 文件夹含 photo.jpg、photo.mov、manifest.json。将一对 JPG/MOV 一起导入 Apple「照片」。本次没有验证最终 iPhone 显示、iCloud 同步或批量导入图库行为。
